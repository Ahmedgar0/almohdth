# طلبات المعرض — دار المحدث

موقع لاستقبال طلبات شراء الكتب من معرض الرياض للكتاب، بثلاث واجهات: العميل، وفريق الإدارة، وفريق المعرض.

**التقنيات:** React (Vite) + Supabase (قاعدة البيانات ودخول الفريق والصور) + Netlify (الاستضافة). لا يحتاج خدمة بريد ولا رسائل نصية.
الدفع وبوليصة الشحن يبقيان في سلة.

## الواجهات

| الرابط | لمن | ماذا يفعل |
|---|---|---|
| `/` | العميل | يدخل باسمه ورقم جواله، ثم يطلب على ثلاث خطوات: الكتب، العنوان والشحن، المراجعة |
| `/#orders` | العميل | يتابع طلباته ويدفع منها |
| `/#admin` | فريق الإدارة | المراجعة، والتواصل مع العميل، وتأكيد الدفع، والشحن، والفريق، والإعدادات |
| `/#fair` | فريق المعرض | التسعير، ثم الشراء بعد الدفع، ثم التغليف (مصممة للجوال) |

## دورة الطلب

```
العميل يرسل الطلب
   ↓  (بانتظار التسعير) ........ يظهر لفريق المعرض في «التسعير»
المعرض يسعّر كل الكتب أو يحدد غير المتوفر
   ↓  (جاهز لإبلاغ العميل) ...... ينتقل تلقائياً، ويظهر للإدارة
الإدارة تنشئ طلباً يدوياً في سلة، وترسل المبلغ الكامل ورابط الدفع على واتساب
   ↓  (بانتظار الدفع)
الإدارة تؤكد الدفع بعد ظهوره في سلة
   ↓  (مدفوع، قيد الشراء) ....... يظهر لفريق المعرض في «الشراء»
المعرض يشتري الكتب
   ↓  (تم الشراء، قيد التغليف) ... ينتقل تلقائياً حين تُشترى كلها
المعرض يغلّف ويؤكد
   ↓  (جاهز للشحن) .............. يظهر للإدارة
الإدارة تصدر البوليصة من سلة وتدخل رقم الشحنة
   ↓  (تم الشحن) ................ رسالة واتساب للعميل برقم الشحنة
```

- **التسعير مرة واحدة:** الكتاب المطلوب في أكثر من طلب يُسعَّر مرة واحدة في واجهة المعرض، والقوائم مرتبة حسب رقم الجناح.
- **تعديل العميل لطلبه:** إن أراد حذف كتاب بعد معرفة السعر، تضغط الإدارة «حذف بطلب العميل» فيُستبعد من المبلغ.
- **نفاد كتاب بعد الدفع:** يضغط موظف المعرض «نفد»، فيُسجَّل في سجل الطلب لتسترجع الإدارة قيمته.
- **تأخر الدفع:** الطلب الذي تجاوز مهلة الدفع يظهر «متأخراً» للإدارة، مع زر تذكير على واتساب.
- **سجل الطلب:** كل خطوة تُسجَّل باسم من نفّذها.

## الشحن

| الشركة | لمن | التكلفة |
|---|---|---|
| ريدبوكس | داخل المملكة، يصل العميل رابط من ريدبوكس لاختيار الخزانة | 11.35 ر.س |
| سمسا | داخل المملكة، إلى الباب | 26 ر.س |
| DHL | الطلبات الدولية فقط | تُدخلها الإدارة لكل طلب بعد التسعير |

الأسعار قابلة للتعديل من الإعدادات.

الدول المستثناة من الطلب: جميع الدول الأفريقية، واليمن، والعراق، وسوريا، ولبنان، والأردن، وفلسطين، وإسرائيل (لا يتوفر الشحن إليها من المملكة). القائمة في `src/lib/countries.js` وفي دالة `submit_order` في `supabase/schema.sql`، فعدّلهما معاً.

## الدخول والصلاحيات

- **العميل** يدخل بالاسم ورقم الجوال، بلا رمز ولا كلمة مرور. رقم الجوال هو حسابه، ويبقى مسجّلاً على جهازه حتى يخرج.
  - صفحة «طلباتي» تعرض مرحلة كل طلب وكتبه ومبالغه فقط، دون الاسم والعنوان، لأن أي شخص يعرف رقم العميل يستطيع فتحها.
  - العنوان يُعبّأ تلقائياً من آخر طلب على الجهاز نفسه فقط، ولا يُجلب من الخادم.
  - الحد 5 طلبات لكل رقم في الساعة، و300 طلب للموقع كله في الساعة.
- **الفريق** يدخل بالبريد وكلمة المرور، ويغيّر كلمة مروره من داخل واجهته.
- **فريق المعرض** يرى الطلبات باسم العميل فقط، دون الجوال والبريد والعنوان. يسعّر ويشتري ويغلّف عبر دوال محددة في الخادم، ولا يستطيع تعديل السعر بعد إرساله للعميل، ولا الشراء قبل تأكيد الدفع.
- **فريق الإدارة** له كل الصلاحيات، ويضيف أعضاء الفريق من صفحة «الفريق».

## التشغيل (مرة واحدة، حوالي 30 دقيقة)

### 1) Supabase
1. أنشئ مشروعاً في [supabase.com](https://supabase.com)، ويُفضّل اختيار منطقة قريبة (مثل Frankfurt).
2. من **SQL Editor** → **New query**: الصق محتوى `supabase/schema.sql` كاملاً واضغط **Run**.
3. انسخ من Project Settings → API: قيمة **Project URL** وقيمة **anon public key**.

### 2) إعدادات الدخول
في Authentication → **Sign In / Providers** → **Email**:
- أبقِ **Enable Email provider** مفعّلاً، و**Allow new users to sign up** مفعّلاً (تحتاجه صفحة «الفريق» لإنشاء حسابات الموظفين).
- عطّل **Confirm email** حتى يعمل حساب الموظف فوراً دون رسالة تأكيد.

إنشاء الحساب وحده لا يعطي أي صلاحية؛ الصلاحية تأتي فقط من جدول `staff` الذي تديره الإدارة.

### 3) أول مدير
1. Authentication → **Users** → **Add user** → **Create new user**: بريدك وكلمة مرور، مع تفعيل Auto Confirm.
2. في SQL Editor شغّل (بعد تغيير البريد والاسم):
   ```sql
   insert into public.staff (email, name, role) values ('you@example.com', 'أحمد', 'admin');
   ```

### 4) Netlify
1. ارفع المشروع إلى مستودع GitHub، ثم في Netlify: **Add new site** → **Import from Git**.
2. في Environment variables أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
3. اضغط **Deploy**، واربط نطاقك إن أردت.
4. في Supabase: Authentication → **URL Configuration** → ضع رابط الموقع في **Site URL**.

### 5) قبل فتح الطلبات
1. ادخل `/#admin` ← **دور النشر والأجنحة**: الصق قائمة الدور المشاركة وأرقام أجنحتها دفعة واحدة.
2. **الفريق**: أنشئ لكل موظف في المعرض بريداً وكلمة مرور بصلاحية «المعرض»، وأرسلها له مع الرابط `/#fair`.
3. **الإعدادات**: راجع رسوم الخدمة، وأسعار الشحن، ومهلة الدفع، والسياسات.
4. جرّب طلباً كاملاً بنفسك من الجوال، من الإرسال حتى الشحن.

## التشغيل محلياً

```bash
npm install
cp .env.example .env      # ضع قيم Supabase
npm run dev
```

بدون ملف `.env` يعمل الموقع في **وضع العرض التجريبي**: البيانات في المتصفح فقط. رقم العميل للتجربة `500000000`، والإدارة `admin@demo.com`، والمعرض `fair@demo.com`، وكلمة المرور `demo`. افتح كل واجهة في تبويب مستقل لتجرّب الدورة كاملة.
`npm run build:demo` يبني نسخة العرض التجريبي ملفاً واحداً في `dist-demo/index.html`.

## الحماية

- حدود الطلبات لكل رقم وللموقع كله، مع حقل مخفي يصد الطلبات الآلية. ولا يُشترى أي كتاب قبل الدفع، فالطلب الوهمي لا يكلّف إلا وقت التسعير.
- التحقق من الدولة والجوال والعنوان وشركة الشحن يتم في الخادم، لا في المتصفح فقط.
- مراحل الطلب تتغير تلقائياً بمشغّلات (triggers) في قاعدة البيانات، فلا يختل ترتيبها مهما كانت الواجهة.
- الصور تُضغط في المتصفح (أقصى بُعد 1200 بكسل) وتُخزَّن بأسماء عشوائية، وحدّها 3 ميجابايت.
